# 0.9.0-preview.9：中优先级与基础优化

日期：2026-11-04。前一轮优化先提交为 532c41f。本轮不改变普通目录、冲突判断、历史保留数量或双设备基线语义。

## 中优先级

### 变更检查与目录缓存

接入现有 ICloudChanges，使用 OneDrive delta 检查驱动器是否变化。首次只取得 latest 游标，不遍历整个 OneDrive；业务文件清单仍按项目与排除规则枚举。目录和元信息文件清单保存在本机 cache/cloud-inventory/<绑定摘要>.json。

没有云端变更时复用清单。出现变更、账户/项目/根目录/排除规则改变、缓存损坏或缺失、缓存超过 6 小时、完整核查时重新枚举。变更接口不可用时回退到当前项目枚举。新快照在枚举前后分别检查游标，跨越云端变更的扫描结果不写成稳定缓存。

这是“变化时失效、无变化复用”，尚不是逐项套用 delta 的全盘镜像。缓存命中不跳过仓库身份、目标绑定和写入时的实时版本检查；云端删除不会传播到本地。不会为比较下载业务正文。

### 观察记录减少重复写入

metadata/devices 下的观察记录在内容变化时立即发布；内容相同且上次成功发布不足一小时则跳过，一小时后发送下一份完整心跳。真正的文件版本元信息仍随事务及时发布，不受此节流影响。

待发送记录继续在 state/devices/<设备ID>/cloud-outbox 中保存，成功核验云端结果后才删除；丢失上传响应可重试原记录。成功发布摘要在 cache/cloud-observations，清理该缓存只导致额外发布，不丢事务或基线。既有云端观察和版本证据不自动删除。

### 限流与读取重试

同一云盘会话的并发请求按主机共享等待期限，遵守 Retry-After（秒或日期），没有头时采用指数退避与少量随机抖动。最多五次请求。等待可取消，长等待分片，不使用不可取消的睡眠。

读取请求的网络错误、超时和 503/504 可以重试；429 明确拒绝的请求可以重试。结果不明确的写入失败不自动重放，由原事务恢复核实，避免重复创建或移动。Graph 令牌不发送给预授权传输地址的规则保持不变。

## 基础优化

- 主窗口与草稿预览共用 ProgressMailbox，只保留最新进度。主窗口每 150ms 采样，草稿预览仍由原定时器采样；工作线程不再给 UI 队列投递每文件一个回调。主窗口只读预览也接入进度。
- 结构化运行报告新增云端目录枚举、目录缓存命中、元信息缓存命中/读取数、观察记录上传/跳过数、HTTP 请求/重试/累计等待毫秒、云端读取/本地扫描耗时。失败阶段也保留已耗时间。累计并发等待不是端到端总耗时，不用来伪造上传速率。
- 修复日汇总日志一直写 cloud=Unverified 的问题，改为实际报告状态。
- 文件元信息缓存反序列化为空值时重新读取云端，不清除共同基线。
- 未新增 NuGet 依赖、服务或配置项。保留两个文件并发上限、WinForms、SDK 自包含共用依赖和不裁剪发布。
