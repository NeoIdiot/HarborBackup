# 0.9.0-preview.20：按项目 ID 管理，全新配置

日期：2026-11-11。

## 行为

用户要求不兼容旧配置、重新生成。本版项目配置使用 schemaVersion 2，id 是新建时生成的 64 位十六进制标识。旧 schemaVersion 1 明确拒绝，不按路径回填身份、不读取旧项目登记来做迁移。

- 同一项目在本机编辑、跨设备加入、列表合并/选择/移除、文件元数据、设备观察、保护索引、运行状态及确认清单中使用同一 ID。
- 源目录、目标路径、显示名称和云端 folderId 均为属性，不用于计算项目 ID。不同 ID 的同名、同目录条目不合并。
- 新项目编辑窗口只生成一次 ID，显示为只读、可复制的整行字段。多次校验、预览和保存不另建 ID。
- 云端按 metadata/projects/<project-id>/files 保存文件证据，locations 保存不可变的位置修订。位置代数递增，同代按映射 ID 确定顺序；旧映射不会再次发布并覆盖较新位置。文件保护和事务仍核验物理目录、版本及原映射。
- 列表不再用退役恢复映射隐藏旧路径；移除偏好仅按仓库及项目 ID 生效。CLI 支持 --project-id，--destination 仅作可读路径选择器。
- 空项目的首次手动备份也登记 ID，无须先上传业务文件。
- initialize --fresh 在维护/启动互斥和运行锁下生成空新配置；有程序运行则拒绝。原 data 整体留存为同级 data-retained-*，不解析或迁移旧配置、身份和状态，不删除恢复/保护材料或业务文件，不访问云端。新配置需重新连接账户并创建新的管理目录。
