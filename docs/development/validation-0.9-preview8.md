# 0.9.0-preview.8：减少重复工作与受控文件并发

日期：2026-11-04。保持普通云端目录、元信息比较、单份历史、事务恢复和不传播删除的现有行为。

## 实现

- 无变化且已有共同基线的文件：扫描结果一致时直接结束本文件处理，不再重复查找云端父目录/文件、重新观察本地文件或重写同一基线。不创建或推进新基线；下一轮仍重新读取云端目录和本地状态。
- 新建共同基线仍核对云端实时版本和本地观察；事务完成后的 SHA-256 核验保留。Record 对相同哈希也不重复写盘。
- 上传前把原来的强制 SHA-256 观察、再次 SHA-256、QuickXor 三遍内容读取，合并为一次顺序读取，同时计算两种摘要。验证大小、修改时间与预览哈希；同一只读文件句柄保持到上传完成，拒绝并发写入/删除。
- 每个项目最多同时处理两个文件。目录操作为顺序屏障，项目之间仍顺序执行。一批全部结束后检查未完成事务，再决定是否派发下一批；取消时等待当前批次退出后才释放云端连接。
- 目标目录创建/绑定、管理目录缓存、令牌获取分别用小范围异步互斥保护；已确认元信息字典支持并发访问。上传正文不占用这些互斥。
- 不增加依赖，不改变安装布局，不开启裁剪。初版并发上限固定为 2，不新增用户配置项。

## 验证

完整回归 338 项通过：Core 178 / Windows 71 / Desktop 39 / Integration 50；构建无警告、无错误。

新增 11 项覆盖：

- 无变化共同基线：处理阶段额外云端 Find 为 0、下载不增加、基线修改时间不变。
- 新基线：扫描后云端版本改变时拒绝提交；恢复原版本后才建立基线。
- 单遍 SHA-256 / QuickXor：空流、单字节、160 字节、跨 128 KiB 块边界与独立算法一致；不回读、不关闭调用方流；取消不消费输入。
- 两个上传实际重叠，上限为 2，第三个等待；上传期间本地源文件不能被写入，嵌套目录结构保留。
- 上传失败停止后续派发、独立文件可完成、保留事务且恢复成功。
- 取消等待两个在途任务退出，第三个不启动，恢复成功。
- 连续更新保留每文件一份历史；按确认清单并发取回到设备自身目录，旧本地内容先保护。

测试使用临时目录和内存云盘，不使用生产账户或生产文件。上述是操作次数/读取次数与并发边界的确定性验证，不是实际 OneDrive 带宽测试；真实上传速度仍取决于文件大小、网络延迟、带宽与服务限流。两文件分批策略优先保持清晰的恢复边界，尚未使用自适应并发、全盘增量游标或元数据压缩。
