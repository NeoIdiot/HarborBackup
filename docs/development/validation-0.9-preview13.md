# 精简上传流程验证（准备用于 0.9.0-preview.13）

## 实现

- 整轮读取云端目录和可信文件元信息，目录 ID 在本轮复用；新建目录的返回 ID 立即加入缓存。
- 上传执行扫描只读取本地属性并复用仍有效的摘要缓存。需要读取内容时，在两个工作任务中按文件打开源，锁定后一次联合计算 SHA-256 和 QuickXor。该句柄保持到判断、传输和元信息提交结束；不会同时持有整个项目的文件句柄。
- 重新判断内容相同则跳过，覆盖时按扫描到的文件 ID/ETag 条件归档，依靠服务端写入前置条件检测竞争。
- 正常小文件上传、修改时间、文件元信息共三个主要写请求。正常路径不在执行入口、业务层和 Graph 层重复查询目标，也不在上传完成后重新查询和哈希。
- 已扫描目录不会逐文件从根目录重复查找；不存在的目录首次创建后复用。
- 上传/归档/元信息的响应丢失、冲突和旧事务恢复仍进行额外查询，不使用正常路径的简化假设。
- 已确认上传摘要用于记录本机基线；版本判断规则本轮未改变。拉取校验与本地替换保护保留。
- 事务格式仍为 v4，不引入新的状态迁移要求。原版本未完成的 v4 事务继续走核验更严格的恢复路径。
- 不新增依赖。UploadHashPasses / UploadHashBytes 记录执行阶段联合摘要工作；HashBytes 不包含实际上传时再次读取正文的流量。

## 验证边界

正常小文件三次请求指父目录、项目绑定和元信息目录已就绪，服务端正常返回校验值且无重试。整轮目录扫描、授权、目录创建、归档、历史清理和观察记录另计。不是所有文件总共只有三次请求，也不是实际带宽测量。

定向测试覆盖正常创建无 GET、竞争时不覆盖、每文件单次摘要、目录复用、相同内容跳过、元信息响应丢失不重传正文、源锁释放、扫描目录被删除、恢复期间云端变化。

上一轮写回桌面仓库的自动权限审核两次超时，剩余修正与完整验证在系统临时目录的独立副本进行。临时副本基于 8310cca，并合入桌面仓库现有工作区差异。2026-11-05 已将剩余补丁应用到开发仓库，并逐一核对 15 个补丁文件与临时副本一致（本次验证记录更新前）；没有修改正式安装、生产配置或云端文件。发布/安装验收尚未执行。
