# 0.9.0-preview.12 上传流程

## 行为

- 正常更新：比较可信元信息 → 锁定并核对本地源 → 条件归档云端旧文件 → 上传至正式路径 → 核验 → 提交元信息/本机基线。
- 首次上传不创建 archives/conflicts；正常上传不再经过 conflicts/<项目摘要>/<事务>/content。
- 历史正文按 archives/<云端目标路径>/<文件相对路径> 保存；真正冲突按原目录保存，文件名带设备/操作标识。
- 索引保存至 metadata/protection/<种类>/<项目摘要>/<路径摘要>/<操作>.json，正文目录不混放 index.json。
- 上传失败时只在正式路径仍为空的情况下云端复制旧文件回来；其他设备写入时不覆盖。
- 替换已有历史时仅短期保留同目录 .harbor-history-<操作>.tmp 恢复材料。完成后只留上一份普通历史。
- 两个文件持续补位，目录保持依赖屏障；失败停止派发并等待在途事务结束。
- 未修改的共同基线取回时不再上传，避免旧设备覆盖较新的共享历史。
- 修复并发元信息缓存文件共享冲突；缓存失败不影响已验证的云端操作。
- 无新增依赖，不裁剪 WinForms。

## 旧逻辑清理与切换

移除 StageLocalAsync、TargetStaging、ProtectionFolderAsync、IndexProtectionAsync、旧数字目录清理和按 content/index.json 遍历的维护逻辑。文件元信息仍读 v2，新上传事务 v4，新保护索引 v2。

旧版本未完成事务必须先用旧版本恢复；本版明确拒绝误读，不删除事务或旧云端保护副本。旧布局数据不会自动迁移/清理。本次不修改生产配置、云端文件或正式安装。多台设备应在无旧事务时统一升级。

GraphDrive 大文件适配器继续使用已验证的唯一临时名称上传会话再条件改名，防止个人账户端点覆盖竞争文件；没有额外保护目录。该协议细节与此次删除的业务暂存执行链不同。

## 验证范围

合成云盘覆盖正常路径、原树历史、单份保留、上传失败回滚、响应丢失、并发目标写入、源文件变化、旧事务拒绝、本机保留、取回历史不倒退、持续补位。协议测试覆盖归档条件移动、条件删除及新时间戳更新。

统计 CloudUploadedBytes/Files 是本轮成功确认的上传正文（含必要的保护上传），不包含元信息，不等于实际线路流量；续传/响应丢失恢复可能不计入该值。CloudUploadMilliseconds 和 FileProcessingMilliseconds 是各任务累计耗时，并发时不能相加当作总耗时。
