# ADR-0008：OneDrive 逐设备文件元信息

> 历史设计：0.6 同步目录模式。当前账户直连规则以 [OneDrive 传输设计](onedrive-account-transport.md) 为准。

状态：0.6.0 实现，0.6.1 调整默认目录。日期：2026-11-01。用户允许优化旧脚本决策；不迁移旧脚本状态。

## 目录与身份

共享目录默认 `<本机 OneDrive 根目录>/HarborBackup/metadata`。对于当前电脑即 `C:\Users\<用户名>\OneDrive\HarborBackup\metadata`。不能把这一绝对路径写死到其他电脑。

```text
OneDrive/HarborBackup/metadata/
└─ projects/<共享项目键>/devices/<设备ID>.json

安装目录/data/state/devices/<设备ID>/
├─ baselines.json
├─ metadata-outbox/<本机任务ID>.json
├─ transactions/
├─ last-run.json
└─ scheduler.json
```

共享项目键为版本命名域及规范化目标相对路径的 SHA-256。两台电脑使用相同 OneDrive 数据集及相同 destination 即对应同一项目，源目录和本地项目 GUID 可以不同。大小写和路径分隔符不造成不同身份；重命名 destination 是新共享项目。不同 OneDrive 账户/数据集不能混用元信息目录。

每台设备只写自己的项目 JSON，读取其他设备 JSON。没有所有设备共同改写的总表，也没有把 JSON 文件锁误作跨电脑锁。Windows 设备身份仍由安装身份及用户身份派生，设备名只用于显示。

## 必要字段与写入

共享 schemaVersion=1。快照包含设备 ID/名称、共享项目键、目标相对目录、单设备修订号、生成时间。每个文件包含相对路径、两端存在/不可用类型、SHA-256、字节数、UTC 修改/哈希时间、本轮是否实际哈希、该设备的共同版本哈希、处理结果、观察时间及曾实际观察的目标版本哈希集合。

源绝对路径、Windows SID/MachineGuid 原值、恢复事务、临时文件名、暂停状态、窗口设置、缓存和完整日志不共享。local outbox 的映射指纹仅保存在本机。其他设备的哈希只作协调证据，绝不作为本机哈希缓存或直接替换本机共同基线。

扫描观察先保存至本机 outbox；逐文件完成结果在内存累积。文件复制、保护、验证、共同基线提交和事务清理在本机完成。项目结束（含取消/失败）时先保存完整 outbox，再发布一份原子 JSON，避免每处理一个文件都重写整份元信息。中途进程终止后，以已持久化的共同基线和下一轮重新扫描重建观察。发布失败保留本机记录并报告 MetadataPublishFailed；下一次备份/恢复会重试。元信息故障不会阻止已有文件事务的必要恢复；新写入遇到不可核验状态会暂缓。

发布时检查本机拥有的共享文件修订号和内容。出现更高修订号或同修订号不同内容时停止发布并保留证据，不用时间戳强行覆盖。修改共享目录只影响后续发布，原目录不删除。设备克隆/丢失本机状态造成身份冲突时，应保留证据并分配不同设备身份，不能清空 JSON 绕过校验。

## 冲突决策

- 有共同基线：仅源修改时允许备份并保护旧目标；仅目标修改时备份提示取回，明确执行取回才写源。单边修改不依赖两台电脑的时钟大小。
- 两端均偏离共同基线且内容不同：保存双方冲突副本，等待用户选择，不以较新的时间戳自动淘汰另一边。
- 初次接入、没有共同基线：保留原有“不同时间较新内容优先、覆盖前保存不同内容；同时间不同内容保留双方”的规则。新设备应先预览或取回，避免把自己的旧副本当成新版本。
- 共享记录报告了本机尚未观察到的目标版本：写入暂缓并报告 AwaitingPeerFileContent。文件内容到达后重新核查。历史已观察的哈希用于容忍旧设备记录滞后，不等同于版本因果链证明。
- 无法读取、格式损坏、不支持版本或发现同步冲突命名的共享 JSON：提示问题并阻止新文件写入；保护已有双方内容和事务恢复仍可执行。
- 覆盖前再次读取共享记录，并继续使用原有文件摘要、大小、修改时间核验与同卷替换协议。

“待处理问题 → 解决选中文件冲突”展示实际源/目标位置、完整摘要、长度和时间。明确选择本机版或目标版后，仅处理该文件；确认后映射或文件变化会拒绝执行。仍需归档被替换的版本，不传播删除，不自动文本合并。

## 界面与配置

“设置 → 共享元信息目录”可选其他 OneDrive 子目录或恢复默认。`storage-settings.json` 新增 `syncMetadata`（默认 true）、`sharedMetadataDirectory`（null 表示上述默认位置）。关闭共享不关闭共同基线的单边/双边判断。手动指定的路径会保留；升级不覆盖它。需要切换到新默认目录时点击“使用默认位置”。目录修改用于后续发布，不删除旧目录中的记录。

“待处理问题 → 设备文件状态”按设备、项目、文件查看观察记录，可筛选并查看完整摘要。这里显示已发布到本机同步目录的观察，可能过时，不能证明云端已上传或其他电脑已收到。CLI `devices [--destination <项目>] --json` 提供同样的只读数据。

同步目录与源、目标、应用数据、保护副本目录必须隔离。使用同一台电脑上不同配置管理相同目标时仍受本机互斥保护；不同软件实例同时管理同一个项目不受支持。

## 边界与运维

OneDrive 对文件内容和元信息分别传输，本实现不能保证它们同时到达，也不能保证尚未收到的离线修改被提前发现。真正并发/断网时仍可能产生 OneDrive 自身的冲突文件。不得宣称分布式强一致或零并发冲突。共同基线、哈希核验和保护副本是恢复依据。

操作交接时确认 OneDrive 无待处理同步，再在另一设备预览/取回。可将元信息目录设为“始终保留在此设备上”；读云占位文件可能需要下载。元信息只含摘要，不携带冲突文件内容；0.7 的新保护副本默认在 OneDrive/HarborBackup/archives 和 conflicts，旧 data/protection 保留，不能只凭 JSON 重建文件。

不按日期自动删除其他设备记录、共同基线或历史已观察哈希。旧设备记录若造成长期未知版本提示，需要核对该设备和实际云文件；不能自动忽略。单快照读取限 32 MiB，超限明确报错，后续大型项目可使用分片协议。未提供账号级 OneDrive API、云端确认和分布式锁。

## 验证

隔离目录模拟两个独立源、OneDrive 根目录、设备身份和本机任务 GUID。显式分步复制元信息/内容模拟乱序，验证单边更新、双方修改、旧时钟、缺失内容、损坏记录、所有者修订冲突、路径逃逸、发布失败重试、只读预览与显式选择后的再次修改。真实 OneDrive 网络、离线长时间交接及多电脑并发仍需环境验收。
