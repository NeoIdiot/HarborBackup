# 0.3 桌面界面重设计

以下记录 0.3 的设计依据。0.4 按反馈移除设置小字说明、页标题副标题和侧栏提示，补充自适应行高、双语与集中帮助；现行交互见 [语言与帮助设计](ui-language-and-help.md)。

## 目标与参考

旧界面的主要问题是大面积强蓝导航、同等权重的操作按钮、空表格占满页面，以及首次启动被呈现为配置故障。此次保留 .NET 10 / WinForms，按 Windows 桌面软件常见的导航、内容、操作层级重新组织界面。

2026-10-28 查阅以下官方开源项目资料，其中 PowerToys 和 Files 的官方界面截图已下载到本机忽略目录并进行视觉对照：

| 参考 | 采用的设计思路 | HarborBackup 中的落点 |
| --- | --- | --- |
| [PowerToys 通用设置](https://learn.microsoft.com/en-us/windows/powertoys/general) | 按用途分组，设置行包含标题、说明和控件 | 本机与存储、自动备份、校验与容错、高级配置 |
| [Files](https://files.community/) / [源码](https://github.com/files-community/Files) | 紧凑侧栏、轻量选中态、工具栏与列表分离 | 五页导航、侧栏选中标记、页面级操作、文件列表 |
| [Kopia 首次使用流程](https://kopia.io/docs/getting-started/) / [源码](https://github.com/kopia/kopia) | 首次启动先引导配置存储与备份对象 | 选择位置 → 添加项目 → 预览并备份 |

## 页面设计

- **外壳**：浅灰侧栏、白色内容卡片、蓝色主操作；保留系统标题栏、缩放、移动和窗口操作。侧栏底部说明关闭与退出的差异。
- **概览**：无配置时展示欢迎卡片、两个配置入口和三步指引；有效但空项目时说明下一步添加项目。有项目后展示状态、上次完成、下次运行与项目摘要。损坏或部分缺失的既有配置仍显示错误，不静默重建。
- **备份项目**：配置管理与选中项目操作分为两组；完整核查、核查并备份、移除放入“更多操作”。取回仍必须先预览再确认。
- **运行记录**：保留项目、结果和起始日期筛选；没有匹配记录时显示说明，不展示空白表格。
- **待处理问题**：保留恢复、筛选、打开证据目录；空视图提示只描述当前筛选结果，不宣称所有文件已安全或云端上传成功。
- **设置**：本机存储入口优先，分组卡片可滚动；保存和重新加载固定在底部。根目录、登录启动单独应用，周期和校验设置显式保存。
- **项目编辑**：源目录与浏览按钮同排，目标路径实时解析，目录/文件排除双列，保留草稿预览、校验和保存。

## 实现与边界

`Styling/AppStyle.cs` 集中颜色、字体与控件工厂；`SurfaceControls.cs` 提供原生 Button、Panel、DataGridView 的轻量绘制和空状态。仍由 `MainForm` 组合页面，`SettingsPage` 管理设置草稿，`DesktopController` 组织用例。没有增加第三方 UI 包、WebView、浏览器进程或常驻动画。

表面控件保留原生焦点、Tab 导航、键盘激活及可访问名称；高对比度使用系统颜色，按钮退回系统绘制。逻辑尺寸按 96 DPI 定义，由 WinForms 缩放一次；自绘按钮的首选尺寸不再叠加主题的 DPI 最小尺寸。设置 UserControl 独立声明 DPI 缩放，表格行高与单元格留白随 DPI 更新。

配置初次缺失与配置故障通过 `DesktopState.NeedsSetup` 区分。欢迎页和设置草稿不创建配置文件、不启用备份；首次缺失配置不触发问题气泡。实际保存和运行继续经过既有协调器与配置编辑器。

不改变备份方向、状态格式、冲突决策、暂停与事务取消规则。不新增暗色模式、自动导入真实配置或自动启用登录启动。

## 验证方法

运行既有文件、事务、兼容和桌面交互测试。新增两种首次使用场景：两份配置缺失时引导配置；损坏 JSON 时继续报错并保留原文件。两者均验证备份按钮不可执行，浏览设置不写入默认配置。

`HostTests` 默认启用 PerMonitorV2；设置 `HARBORBACKUP_SCREENSHOT_DIR` 可输出五个页面、项目编辑、首次使用和配置错误（含最小窗口）的 DrawToBitmap 渲染图。设置 `HARBORBACKUP_UI_DPI=96` 可另行执行 96 DPI 渲染回归，无需修改系统显示设置。测试图使用合成配置，只写入忽略的 artifacts。

渲染图用于控件布局检查，不等同于桌面截图或跨屏动态 DPI 切换验收；真实屏幕与无障碍工具检查需单独记录。最新测试、安装与体积结果见 [实际验证记录](development-validation.md)。
