# ADR-0004：事务 v2 与实际被替换版本保护

- 日期：2026-10-28
- 状态：已实现，隔离目录验证通过；生产切换未执行

## 决定

files.json 保持 schemaVersion=1，status.json 保持 schemaVersion=2。新建文件事务显式使用 schemaVersion=2，绑定设备、任务、源/目标根、相对路径、模式、预期两端版本、保护类型及确定的暂存/回退名称。

覆盖前仍先保存并核验旧版归档；提交使用同卷 File.Replace 并将实际被替换文件保存在同目录 .autobackup-<id>.rollback.tmp。这样检查后出现第三个版本时，原先归档、新版、实际被替换版都有证据。源在提交期间以不允许写入和删除的共享模式持有读句柄。新建使用拒绝覆盖的 File.Move，不用删除原文件降级。

回退材料与状态都核验后才清理。恢复不重新执行文件覆盖：读取现场，完成已发生的保护/状态提交，或让下一次正常运行重新决策。完整暂存可能是唯一版本时先存入冲突目录；不完整暂存、未知第三版、未知映射均保留待处理。

阶段只作提示，磁盘内容决定恢复；不宣称文件与多个 JSON 构成原子事务，也不承诺断电和云端跨设备一致性。

## 兼容与回退

C# 接受旧 v1 事务并保守恢复。旧 PowerShell 仅接受 v1，不能处理新的 v2 未完成事务。回退前先停止新触发，使用相同版本 C# 恢复全部事务，检查证据与状态，再完成受控回退验证。不要把 v2 的版本号改成 1，或删除记录让旧程序继续运行。

JSON 更新也保留替换时实际移出的旧 JSON，签名不符则报错并留下 .previous/.tmp。此机制检测部分外部变化，不是分布式原子比较交换。未知材料需人工核查，不提供批量清理命令。

## 验证

事务关键阶段中断后重复恢复两次；替换窗口第三版竞争；状态提交外部变化；归档失败/半写；源变化后的唯一暂存保护；文件占用；同时间冲突去重；取消后当前文件完成；旧 v1 记录恢复。具体执行结果见 [验证记录](../development-validation.md)。
