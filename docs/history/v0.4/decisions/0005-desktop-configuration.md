# ADR-0005：主窗口、共享控制器和配置草稿

- 日期：2026-10-28
- 状态：已实现，隔离验证通过
- 补充：ADR-0003 的入口行为，手动启动现在打开主窗口；登录启动仍进入托盘。

## 决定

保留 WinForms 与既有四产品工程，Tray 继续作为唯一桌面宿主。TrayContext 只管理应用生命周期、托盘与窗口；DesktopController 管理调度、任务协调和统一 DesktopState；MainForm 与页面显示状态并提交操作；ConfigurationPresenter 组织配置校验、预览和保存。备份逻辑继续经 Core 与 Windows 适配器执行。

主窗口包含概览、项目、记录、问题和设置。普通关闭隐藏窗口，显式退出才停止应用。重复启动通过当前用户、当前会话范围命名管道发送单字节显示请求；不在管道中接受路径或备份命令。托盘实例锁与旧运行 Mutex 保持分离。

ConfigurationReader 的读取与内存解析共享规则；ConfigurationDraft 保存原始 JSON 树及签名，允许表单只修改支持的字段。草稿预览走只读用例。保存取得兼容运行锁，校验、检查两份配置签名，并原子写入选中文档。配置映射/排除变更检查所有本机可见设备的事务；损坏或不可读现场阻止变更，不猜测为空。

缺少配置时仅在内存提供默认草稿。首次保存可以先初始化无项目的配套文件，再保存选中文档；中断可能留下空配置，但不立即执行业务复制。支持空 folders 作为未配置/全部移除状态，调度不启动空项目运行。

本机窗口与目录偏好存于 LocalAppData 下按配置路径区分的 ui.json。明确启动参数优先于偏好；本机暂停仍沿用设备 control.json。文件状态和事务版本保持原状。

## 行为与限制

运行期间草稿可编辑，保存不能与备份并行。外部配置修改使保存失败，草稿保留；不实现自动合并。不同配置文件的保存不是整体原子事务。源根不可用时完整校验会阻止保存；未知 JSON 结构不按空文档覆盖。

后台进度增加类型化阶段、项目、文件、处理数量和观察哈希字节；扫描未确定总量时使用活动指示，不伪造百分比。当前字节指标不代表全部事务 I/O。

本轮只借鉴开源软件的布局和交互，没有复制第三方源码、图标或引入控件库。参考 [WinUI Gallery](https://github.com/microsoft/WinUI-Gallery)、[Duplicati 配置流程](https://docs.duplicati.com/getting-started/set-up-a-backup-in-the-ui)、[KopiaUI](https://kopia.io/docs/getting-started/)。

## 验证

覆盖字段/表达式保留、配置冲突、未完成事务阻止修改、空项目和首次初始化、草稿预览无写入、互斥、取消后再运行、日志损坏隔离、命名管道激活；STA 界面测试实际通过控件新增项目和保存周期，验证关闭/激活保持同一窗口，并导出布局图片检查。
