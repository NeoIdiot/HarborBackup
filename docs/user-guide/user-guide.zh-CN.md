# HarborBackup 0.7 使用说明

程序、私有运行时和本机数据位于当前用户 Programs/HarborBackup 下。app 为程序及 SDK 自包含发布的未裁剪运行时，data/config 为设置。升级和卸载保留 data；关闭主窗口仍在托盘运行。

## 在多台电脑接入同一项目

1. 每台电脑安装此版本，在设置中选择该电脑的 OneDrive 根目录。
2. 为同一项目填写相同的目标相对路径，例如 Projects/Demo；源目录可以不同。
3. 默认共享元信息位于 OneDrive/HarborBackup/metadata。也可在“设置 → 共享元信息目录”选择同一个 OneDrive 子目录。
4. 新电脑先等待 OneDrive 同步，再预览项目。有目标更新时明确执行“取回更新”，建立本机共同基线后再继续编辑。

软件只确认本机文件处理结果，不确认云端上传完成。可将元信息文件夹设为“始终保留在此设备上”；这保证本地可用，不保证其他电脑的最新记录已到达。

## 查看和处理冲突

“待处理问题 → 设备文件状态”显示各设备记录的逐文件哈希、共同版本、结果和观察时间；“查看选中详情”可看完整哈希。CLI 可运行 `devices --json` 查询。

有共同基线时，单边修改按方向备份或取回，不用时间戳判定谁更新。双方均修改时保留双方，选择相应问题行后点击“解决选中文件冲突”，核对路径与版本并选择“采用本机版本”或“采用目标版本”。被替换内容仍保存保护副本；确认后发生修改会拒绝覆盖。

没有共同基线的首次接入仍采用保护后较新内容优先，同时间不同内容不覆盖。请先预览，不要直接让一份旧本地副本参与自动备份。

显示“其他设备报告的文件版本尚未到达本机”时，等待 OneDrive 同步文件内容后重试。元信息损坏、出现同步冲突副本或所有者修订异常时保留现场，核对设备与云文件，不要通过删除状态绕过检查。发布失败时，本机记录保留，可再次备份或恢复重试。

## 数据目录

主窗口和 CLI 共用 projects.json、backup-settings.json、storage-settings.json。语言及窗口设置位于 desktop-settings.json。

state 存储共同基线、事务和 metadata-outbox，不能作为缓存清理。cache/hashes 可重建；history 是运行记录，logs 是诊断日志；新保护副本默认进入 OneDrive/HarborBackup/archives 和 conflicts。旧 data/protection 文件保留，元信息 JSON 不能还原文件内容。

登录启动需要在设置中启用。程序使用随包运行时，运行时更新随软件版本发布。0.4/PowerShell 状态不导入。sharedMetadataDirectory=null 使用默认共享路径；syncMetadata=false 停止共享，不关闭本机共同基线判断。

## 共享存储和本机保留

默认 OneDrive/HarborBackup 下有 archives（历史版本）、conflicts（冲突副本）、metadata（文件状态）。在设置中修改共享存储根目录，未单独指定的三个目录随之变化；各目录也可以单独选择或恢复默认。路径保存后立即显示，尚未添加项目也可以配置。已有自定义路径不会被覆盖。

历史版本和冲突副本分别选择“始终保留在本机”或“仅联机”，默认前者。这是每台电脑自己的保留偏好，都仍通过 OneDrive 同步。仅联机不是删除文件：事务完成且客户端报告已同步后才请求释放内容，保留占位文件，下载/释放均可能需要等待。本地可能临时保留部分内容，断网时不保证可以恢复。元信息和副本索引请求保留本地。

“文件保留状态 → 状态详情”区分等待注册、等待同步、已请求下载/释放、已保留本机、按需文件及失败重试。托盘运行时每分钟处理一批；每次备份/恢复结束也会处理。退出程序停止自动重试，但记录持久保存。“应用到已有副本”扫描当前目录，仅登记本设备创建的受管理副本；不改变其他电脑的设置。

位置变化不移动或删除旧文件，“旧保护副本 → 查看原位置”列出已知原目录。已有事务时禁止更改存储；升级遇到旧本地默认目录的未完成事务，先沿用旧位置恢复，再启用新默认。不要通过清空 state 或删除共享文件释放空间。
