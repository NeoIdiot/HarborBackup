# HarborBackup 0.9：普通目录备份

## 安装时自动检查配置

安装器会在启动软件前自动检查本机数据。首次安装自动生成空的新配置；旧项目格式、旧账户/运行状态格式、缺失或损坏的必要配置会自动重建。原本机 data 完整留存在同级 data-retained-* 目录中，不迁移旧项目或旧状态，不删除源文件或云端文件。无需运行重建命令。

当前格式的数据正常保留；重复安装不会重置项目、凭据或恢复材料。检查不要求源目录存在或云端在线。配置文件被占用等读取错误会中止安装并保留原数据，解除占用后重新安装即可。

发生重建后，安装完成直接打开软件、连接账户，创建新的管理目录并添加项目。业务备份目标可以选择原来的普通目录；首次上传或拉取按预览明确选择。

新建项目生成固定的 64 位十六进制 ID，编辑窗口可查看和复制。改名、修改源目录或目标路径均保留 ID。另一台设备应使用“加入云端项目”沿用同一 ID。不同 ID 表示不同项目，即使名称或目录相同。

## 设置位置

1. 在“设置 → 账户与管理目录”连接个人 OneDrive 账户，选择 HarborBackup 管理目录并应用设置。这里保存元数据、历史版本和冲突副本，不是备份正文目录。已有管理目录可以继续使用；普通非空目录不要当作管理目录。
2. 在“备份项目 → 添加项目”选择“本地目录”。
3. 使用“浏览云端…”选择项目最终目标，或在“云端目录（相对 OneDrive 根目录）”中填写路径，例如 Projects/DROP_CODE，即 OneDrive/Projects/DROP_CODE。根目录是固定起点，各项目保留自己的相对目录。新输入的目录在首次上传时创建；文件直接放到该路径下，不追加项目编号或版本编号。
4. 核对云端相对目录，预览后保存。编辑窗口和列表不再重复展示“实际目标”。另一台设备连接同一管理目录后可“加入云端项目”，选择自己的本地目录。

项目已记录云端目录时，“浏览云端…”优先打开该目录。“浏览云端…”会短时缓存已读取的目录，并在显示当前列表后预先读取部分下一级目录。返回上一级或重新打开选择窗口时，可以复用尚未过期的列表，减少重复等待。需要查看其他设备刚创建、改名或移动的目录时，点击“刷新”读取当前位置的最新列表；刷新失败会保留原列表和当前位置。关闭窗口会取消尚未完成的读取。浏览和选择目录不上传或下载项目文件。

目录示例：
```text
OneDrive/Projects/DROP_CODE/原文件及子目录
OneDrive/HarborBackup/metadata/共享状态
OneDrive/HarborBackup/archives/上一份历史
OneDrive/HarborBackup/conflicts/待处理副本
```

项目目标不得与管理目录或其他项目目标重叠。已存在的普通非空项目目标可以选择；首次没有可信元数据的文件会保留并显示待处理，不会自动覆盖。

项目编辑窗口的“预览草稿”会显示云端读取、本地扫描、处理数量和耗时。可以点击“停止预览”保留草稿，或关闭窗口请求取消；停止后可修改规则并重新预览。

预览窗口的“排除规则…”展示本次实际采用的全局与项目规则，以及本地/云端跳过数。目录名规则会排除任意层级的同名目录及其子树；不需要追加 `*`。目录按一项计数，不为统计而扫描被排除的子文件。预览草稿无需先保存配置。

“全局排除”提供 Word、Excel、PowerPoint 临时/锁定文件、Windows 缩略图缓存、Windows 文件夹设置、macOS 文件夹信息六项内置规则，默认全部不选。选项旁显示实际表达式，勾选后对所有项目生效。下方仍可每行手动输入排除目录或文件；内置、全局自定义和项目规则合并执行，取消内置项不会移除手动规则。Word 内置项采用 `~$*.docx`、`~$*.doc`，不匹配 `~方案.docx`；需要更宽范围可手动填写 `~*.docx`。文件名匹配不区分大小写且适用于任意层级。预览详情区分规则来源并展示最终有效规则。保存仅改配置，不删除已有文件、历史或恢复材料。规则变更在下次扫描生效，保留已有备份状态，自动备份继续按增量执行；取消排除后，文件重新参与正常比较，有共同基线则继续使用，双方修改或无基线且内容不同的文件等待明确选择。此前因规则变更进入“待首次上传或拉取”的项目，在设备、账户和实际目录一致且旧证据有效时接续旧状态；真正切换目录的项目仍需首次确认。

## 备份与取回

传输默认最多同时处理 8 个文件，云端文件元数据最多同时读取 4 条；目录依赖和限流等待仍会约束实际并发。普通上传合并了重复的恢复记录写入，下载把两种摘要校验合并为一次读盘。云端仍是原文件、原目录，不打包成压缩档；覆盖保护、取消后的恢复和最终核验保持不变。实际提速取决于小文件数量、网络延迟、磁盘和服务端响应。

设置中可分别指定上传、下载速率（KiB/s），0 表示不限。所有并发文件共享同一方向的上限；此设置限制本机传输正文，不限制云端内部复制。单轮内容/时间预算控制自动备份总工作量，速率上限控制网络占用，两者可以同时使用。

断网时，界面和托盘显示“等待网络”，到期任务会保留，实际受理运行后才推进下次时间。Windows 检测到网络恢复后，桌面程序等待约两秒再检查 OneDrive；符合条件的原任务会自动续行。OneDrive、代理或连接暂时故障也会按约 15 秒、30 秒、1 分钟逐步退避到最多五分钟，服务端要求更久时遵守其重试时间。服务冷却等长重试等待会释放运行锁，不持续占用文件工作线程。若备份项目页正在显示，因断网中断的云端列表仍会自动重试一次。上次运行的结果和恢复材料始终保留。

运行详情区分“等待自动重试”“需要确认版本”“需要修复后重试”和“已停止”。单纯网络等待保留原因和原任务，不弹出需要人工处理的故障通知；同项目的真实冲突或授权问题仍会显示。自动续行会重新核验原文件、云端版本和目录映射；上传成功但回执丢失时先核对现场，只缺提交或状态上报时补齐收尾。需要选择版本、重新登录、修复权限或核对损坏记录时，按详情中的具体原因处理。主动停止、暂停不会因为联网事件自动重新开始。

首次明确上传或取回因断网中断后，可自动继续原来已授权的任务；未勾选文件和后来新增的文件不纳入这次续行，项目仍要满足完整完成条件才进入自动备份。原任务已完成的文件后来再次变化时，需要重新预览或等待正常比较。快速网络重试沿用原自动任务的预算消耗；新的正常周期才可使用新一轮预算。

正式安装版通过 Windows 通知中心提示需要处理的故障。点击通知可以打开“待处理问题”，运行详情也可在“运行记录”查看。同一问题持续出现时合并提醒。通知的显示由 Windows 设置控制。

添加项目并保存时，会先检查所选云端目录。已登记的目录会提示“接续已有云端项目”，确认后沿用原项目身份，保留本次选择的本机目录和排除规则；同一项目已加入本机时会提示编辑原项目，不再重复添加。未登记但非空的目录会打开“首次内容核对”，明确确认后才保存配置。取消或读取失败不保存。核对只读，双方已有文件均保留；保存后仍需明确上传或取回，成功后才恢复自动备份。添加时需要连接账户完成目录检查；编辑已有项目仍可离线保存。

“添加项目 / 编辑项目”通过“自动备份模式”下拉框选择：

| 模式 | 业务文件方向 |
| --- | --- |
| 仅上传（默认） | 本地目录 → OneDrive |
| 双向备份 | 上传本地更新，下载云端更新 |
| 仅下载 | OneDrive → 本地目录 |

项目列表显示当前模式。设置只保存在本机，各设备分别选择；定时执行、窗口和托盘的“立即运行”、CLI `backup --automatic` 均按各项目模式处理，继续使用全局暂停、速率限制和自动预算。“立即运行”仍要求项目先完成首次手动操作，自动备份暂停时不可用。“上传选中”“下载更新…”保留明确的手动方向，自动备份暂停时仍可执行，且不受自动预算限制。

“仅下载”不把本地业务文件上传到项目云端目录；管理元数据、覆盖前用于保护本地不同内容的副本仍可能上传。三种模式均保留另一端独有文件，不传播删除。

双向备份按共同基线判断方向，不按修改时间选择覆盖。单侧缺失的文件在模式允许该方向且内容证据可信时由另一侧补齐；双方修改且内容不同，或没有共同基线且内容不同，仍保护冲突并等待明确选择。证据不足的云端文件不会自动下载。比较不下载正文，确定下载计划后才执行取回，核对云端版本及本地内容，保护不同旧内容并在核验成功后提交共同基线。不传播删除，因此单侧删除的文件可能在后续自动运行中补回。

切换自动模式保留已有映射、基线和初始化状态，新项目或实际目录切换后仍需先完成一次手动上传或拉取。已核验原授权的网络中断任务可安全续行；旧记录缺少任务授权、版本冲突或映射证据不符时，相关文件保留待确认或按原目录手动恢复，同项目其他安全文件可继续。手动上传不改本地源文件，手动下载不改云端正文。projects.json 中的 `automaticBackupMode` 可选 `upload`、`bidirectional`、`download`；旧布尔配置的读取规则与非法值处理见[配置示例](../../config/examples/README.md)。

配置草稿点击“预览”后，可查看运行计划及“配置变更影响”：预计传输大小、需保护的旧内容、待处理条目，以及新增排除和重新纳入的条目数。范围数量是两次只读观察的估算，目录按观察条目统计；目录切换或观察失败时不提供确定数量。保存配置仍可离线进行，预览不会代替保存或执行前核验。

“完整核查（只读）”与 CLI `verify` 按一致、内容不同、本地缺失、云端缺失、证据不足、类型冲突分类。依据是本地 SHA-256 和受版本核验的云端元信息，不下载云端正文；证据不足不会算作一致。JSON 报告提供 `verification`、`verificationEvidence` 和 `summary`，核验发现差异或无法确认时返回待处理码 2，读取失败返回 1。

设置中的自动备份内容和时间预算默认均为 0（不限），只约束自动备份。达到预算后不再启动新文件，已开始的传输继续完成并核验，未开始的文件在下一轮增量继续。内容预算按已启动文件大小估算，单个在途文件可能使实际内容超过上限；协议开销和云端内部复制不计。手动备份、取回和恢复不受自动预算限制，原有单轮硬时限和用户停止仍可取消在途操作。预算停止单独记录为 `BudgetLimited`，不会当成用户取消；并存的文件错误仍会显示为待处理。

写入前的单文件读取失败（例如文件被占用）只延期该文件，其他文件继续。授权、网络或身份异常停止该项目的后续派发；写入阶段无法安全判断影响范围的错误保留事务并停止派发，避免将恢复或凭据故障当成普通文件占用。运行报告的 `failureKind` 区分文件不可用、网络、授权、恢复、预算和取消。

网络、授权等运行失败返回码 1；单文件暂不可用、待确认冲突和预算停止返回码 2；取消返回 130。预算停止时若还存在其他错误，整体仍显示待处理或失败，详情保留预算原因。
判断变化只用云端元数据、文件标识、版本标记、大小及摘要，不下载业务文件来比较；本地按大小、UTC 修改时间和核查周期复用 SHA-256。完整核查只重新哈希本地文件。
“上传选中”和“下载更新…”会显示操作预览。勾选不同内容并确认，表示使用所选方向的版本；覆盖前保护另一端的旧内容，校验成功后由软件记录共同版本，无须单独建立基线。CLI 可通过 preview --prepare-upload 或 preview --direction Pull 输出报告，再用 backup/pull --selection 执行确认清单。未确认的差异不会被强制覆盖。

切换本地目录时直接保存即可，保存只更新配置，不迁移或同步文件，也不要求目录已经存在。新目录先完成一次手动上传或拉取，随后继续原来的自动备份策略。拉取可在执行时创建本地目录。

编辑已有项目的源目录或目标路径会保留项目身份，旧映射不会重新出现在本机列表。云端目录改名或移动后，刷新列表会显示当前名称；同一项目 ID 的位置记录仍只显示一项。修改目标路径不会移动旧目标中的文件；后续上传、拉取使用新配置。

预览选择、问题处理、冲突确认和历史版本关联均使用项目 ID，显示路径仅供识别当前位置。项目改名后，同一项目的旧路径归档仍可列出并另存；恢复会核验归档原位置。缺少可核验项目 ID 的旧报告只能查看，不能据其直接处理文件。

选中项目后，在“更多操作 → 移除项目…”可从本机列表移除本地项目或仅云端项目。仅更新本机配置，不删除任何本地或云端文件，也不删除历史、冲突和恢复材料；不会影响其他设备。移除的云端项不会在刷新或重启后再次出现。如需重新加入，可通过“添加项目 → 浏览云端…”选择目录并保存。

未完成操作不阻止保存和预览。预览仍显示文件，仅将涉及未完成操作的路径标记为暂不可写；同项目其他文件可以继续处理。需要恢复时，在“待处理问题”选择“恢复未完成事务”，恢复仍使用原目录。不要删除恢复记录来解除提示。

“备份项目 → 取回云端项目…”用于从另一台设备接续项目：选择云端项目、选择本机保存目录、勾选预览清单、确认取回。新项目在确认后才加入列表，取消预览不会保存配置；已加入的项目使用已有本机目录。“加入云端项目”仍只保存映射，不下载正文。

预览显示云端来源、本机写入目录、新增/更新数量和预计正文下载量。仅执行勾选项；确认后新增的云端文件不自动纳入。文件或项目映射在执行前变化时跳过，并提示重新预览。普通取回保留本机独有修改，不传播删除；已确认云端存在而本地缺失的文件会补回。取回中断后的项目配置和事务保留，可检查记录后恢复。

## 历史和保护

“待处理问题 → 独立目录恢复”可浏览云端当前文件和上一份归档，按路径筛选并勾选恢复。输出目录必须独立于项目源目录、程序、数据和保护目录；原文件和已存在的输出不覆盖。下载前后核对云端版本，下载后核验 SHA-256；缺少可信摘要时显示证据不足，不把它算作通过。此操作不建立共同基线，也不激活自动备份。

恢复演练在指定输出根下建立新的独立目录，支持单轮字节预算和分组轮换，保留恢复文件及 JSON 报告以便检查。预算不能容纳的单个文件会跳过；若需核验它，请增大预算。项目列表用短文字显示保护状态，保持单行高度；悬停状态或选择“更多操作 → 查看项目状态…”可查看最近完整成功、最近恢复核验的范围和文件数、已知积压及首次记录时间，概览也保留这些详情。积压数量是已观察到的下界；部分选择、预算或失败可能使数量不完整，“无已知积压”不证明未观察文件已核验。已知积压持续达到 24 小时，或最近完整成功距今达到 24 小时，才触发相应提醒；更换目录不会继承旧映射的成功状态。

托盘始终保留蓝色锚形图标，状态显示在右下角：循环箭头表示正在运行，琥珀色感叹号表示待处理，红色叉号表示失败或需要修复，暂停符号表示自动备份暂停，短横线表示等待连接、网络或自动重试。没有角标表示空闲，不代表所有文件已备份。悬停可查看状态及待处理文件数量；主窗口提供完整详情。

主窗口按 ESC 与点击右上角 × 相同：关闭主窗口，保留托盘图标，正在执行的任务和后续自动备份继续运行。可通过托盘重新打开主窗口；弹窗打开时，ESC 优先由当前弹窗处理。需要结束后台运行时，使用“退出程序”。

主窗口侧栏可拖动右边界调整宽度，较窄时只显示导航图标；退出程序时记住宽度。

普通历史只保留上一份；新内容提交成功后才清理更早的已提交历史。未解决冲突和未完成恢复材料不按此规则清理。
仅云端保留不下载保护副本；同时保留本地会下载到 data/protection。若另行运行 OneDrive 桌面客户端，它仍可能按自己的设置下载云端目录。
覆盖前先保护不同的云端内容，再上传并校验当前本地文件。保护与上传之间，目标可能短暂缺失；中断时保留文件和事务，有效的原任务可核对归档后继续或恢复缺口，其他情况使用“恢复未完成事务”检查处理。不要手动清理 state 或正在使用的保护目录。

## 升级与凭据

0.8 的数字版本目录保留，不自动搬迁、删除或接管。0.9 中 destination 直接相对 OneDrive 根目录解析：DROP_CODE 表示 OneDrive/DROP_CODE，如需 Projects/DROP_CODE 请编辑后预览。0.8 的事务不能按普通目录布局执行。

本地缺少文件时，尚未写入的中断拉取可直接在“下载更新…”中勾选重新下载，无需先到其他页面恢复事务。预览只显示计划，执行时核对当前文件和恢复记录，保留原记录后发起新下载。预览后文件发生变化则跳过，重新预览即可核对新状态。

当前项目的中断备份可通过“恢复未完成事务”手动重试。程序先原样留存旧事务，核对上次上传和归档的现场；必要时恢复云端缺口，并保留保护材料。随后直接使用当前本地文件重新上传，覆盖前保护云端不同内容，上传核验完成后才提交共同基线。本地文件可在中断后继续编辑，不需要改回旧版本。再次失败会留下新的可恢复事务。网络自动续行只延续原授权，不取得“采用当前本地版本”的手动选择；旧意图未写云端且可安全关闭时，已初始化项目才可按当前模式重新三方比较。只读预览不会执行恢复。

旧目录映射和其他旧格式事务仍通过“恢复未完成事务”核验处理，必要时恢复被移走的云端原文件并保留材料；当前方案不会把它们当成当前目录的新备份。能够确认归属的未完成操作只限制相关文件；不影响保存配置。无法识别的格式或缺少原映射时，查看条目详情中的具体原因，不要删除 state 来跳过检查。

运行记录的“项目”列显示本次涉及的项目；批量运行显示数量和名称。“查看选中详情”或双击会打开独立窗口，可按项目切换、搜索、仅看待处理，并查看简短错误说明和日志路径；完整的原始诊断保留在运行记录和日志中。关闭后返回原列表位置。“待处理问题”只列出最近结果中的待处理条目，不混入历史报告的成功动作。

应用已内置公开 Client ID，通常不必填写。自定义应用可在高级设置填写公开 ID，不填写密钥。凭据仅在本机按 Windows 用户加密，不同步到 OneDrive。断开连接不会删除云端文件。

## CLI

文件操作结果与设备状态上报分别处理：文件已完成但状态暂未上报时会提示并重试。云端项目列表加载慢时仍可编辑、保存本地配置。运行状态读取失败会单独显示诊断，配置仍可编辑；自动备份控制记录无法核验时暂停自动运行。仅修改已保存仓库的本机保留偏好不要求联网或先恢复事务。

```text
HarborBackup.Cli.exe cloud-connect
HarborBackup.Cli.exe cloud-bind --name HarborBackup
HarborBackup.Cli.exe preview --json
HarborBackup.Cli.exe backup --json
HarborBackup.Cli.exe pull --destination Projects/DROP_CODE --json
HarborBackup.Cli.exe recover --json
HarborBackup.Cli.exe devices --json
```

devices 读取共享文件元数据；verify 完整核查本地文件。cloud-inspect / cloud-resolve 支持明确确认后的冲突选择。

CLI `backup --automatic` 在下一次调用时使用与桌面相同的安全续行规则。CLI 退出后不驻留监听网络；需要自动唤醒时保持桌面后台运行，或由现有计划再次调用 CLI。

指定项目时建议使用 `--project-id <项目ID>`，包括 pull、cloud-inspect 和 cloud-resolve。`--destination <当前相对路径>` 仍可作为入口的便捷选择，解析成项目 ID 后执行；两种参数不能同时使用，未知项目 ID 不会退回同名目录。

独立恢复命令（`--path` 为可选相对路径前缀，`--scope` 支持 `current`、`archive`、`all`）：

```powershell
HarborBackup.Cli.exe restore-list --destination "Projects/Demo" --scope all --json
HarborBackup.Cli.exe restore --destination "Projects/Demo" --scope archive --path "docs" --output "C:\RestoreReview" --json
HarborBackup.Cli.exe restore-test --destination "Projects/Demo" --scope all --output "C:\RestoreReview" --max-bytes 104857600 --groups 7 --json
```

`restore-test` 的字节预算 0 表示不限，分组数为 1–256；轮换游标属于可重建缓存，删除缓存后会重新轮换。最近核验时间只证明报告所列范围的正文核验，不能代表所有文件均已检查。`recover` 仍专用于未完成事务。
安装包通过 SDK 标准自包含发布携带 WinForms 所需运行时，不启用裁剪，无须另外安装 .NET。程序和运行时统一放在 app，配置与运行数据保留在 data；升级会清理旧 runtime 目录。真实单账户隔离目录往返已验证，两个实体设备及正式业务升级仍应先用小项目验收。
